# 権限管理 (Permissions)

**言語:** [English](../permissions.md) | 日本語

`/permissions` コマンドを使うと、セッションの権限モードの切り替えや、承認待ちになっている操作の確認・許可を行えます。

---

## 3つの権限モード

新しいワークスペースは初期状態で **Read Only**（読み取り専用）で起動します。モードを変更するとワークスペース単位で保存され、Host の再起動やセッションの再開（`/resume`）後も最後に選んだモードが引き継がれます。

| モード | 自動で実行される操作 | 確認が必要 / 拒否される操作 |
| --- | --- | --- |
| **Read Only** | 読み取り系ツール（`read`, `grep`, `glob`, `ast_grep`, `ViewImage`, `SkillUse`）および読み取り専用と判定された Bash コマンド | ファイルの書き込み・編集、および特権的な Bash コマンドは**拒否**される |
| **Ask for Approval** | 読み取り系ツールと読み取り専用 Bash コマンド | ファイルの書き込み・編集や特権的操作の実行前に**一時停止し、人間の承認（Allow / Deny）を待つ** |
| **Full Access** | 上限ポリシーで許可されているすべての操作が確認なしで実行される | 個別の承認確認なし（ワークスペース境界と上限ポリシーは引き続き適用） |

---

## 承認リクエストの確認手順

**Ask for Approval** モードを選択している場合：

1. エージェントがファイル編集やコマンド実行を要求すると、画面下部に「承認待ち」のバナーが表示されます（または `/permissions` で開きます）。
2. 表示されたツール名、コマンド内容、または対象ファイルを確認します。
3. **Allow**（初期選択）または **Deny** を選んで決定します。

### 承認のルール

- **1操作ごとの許可:** **Allow** はその1回の操作に対してのみ有効です。以後の操作をすべて確認なしにするには、モード自体を **Full Access** に切り替えます。
- **時間制限なし:** 人間の承認待ちにはタイムアウトがありません。
- **停止・モード変更時のリセット:** セッションの停止やモード変更を行うと、保留中の承認待ちはキャンセルされます。セッション停止中は実効モードが `Read Only` になり、`/resume` で再開すると保存されていたモードに戻ります。
- **画面離脱 (`Ctrl+D`) 時の維持:** ターミナルからデタッチしても選択中の権限モードは変わりません。

## Claude とサブエージェントでの扱い

- **Claude Code:** Claude Code 内蔵ツールの呼び出しも Unreal の承認フックを通ります。Claude Code 自身が Bash コマンドの実行を辞退した場合は、Unreal の通常の Bash 操作として扱われ、現在の権限モード（`Read Only` / `Ask for Approval` / `Full Access`）が適用されます。
- **サブエージェント（子エージェント）:** 子エージェントは親セッションの権限モードを引き継ぎます。子ごとに別々の承認画面を開くのではなく、親エージェントが子の要求を受け取り、ユーザーの判断が必要な場合のみ確認を求めます。

---

## セキュリティ上の適用範囲（重要）

- **OS サンドボックスではありません:** これらの権限モードは Unreal ハーネス内の認可を制御するものであり、**OS レベルの隔離（コンテナや VM）を行うものではありません**。実行を許可されたシェルプロセスや外部プログラムは、OS が許可する範囲の環境にアクセスできます。OS の隔離が必要な場合は Docker Sandbox や VM を併用してください。
- **ネイティブファイルツールのワークスペース制限:** **Full Access** であっても、Unreal のネイティブファイルツール（`read`, `write`, `edit`, `grep`, `glob`, `ast_grep`, `ast_edit`）はセッションのワークスペースルート配下に限定されます。ワークスペース外のパスは常に拒否されます（Bash コマンドにはこのパス制限はありません）。

ファイル変更のロックや競合防止の仕組みについては [ツールとファイル変更](tools.md)、ポリシーの構成については [アーキテクチャ](architecture.md) を参照してください。
