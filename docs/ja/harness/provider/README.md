# プロバイダ構成とレジストリ (`harness/provider`)

**言語:** [English](../../../../harness/provider/README.md) | 日本語

`harness/provider` パッケージは、利用可能な LLM プロバイダとモデルカタログを管理し、非秘匿のランタイム選択情報（`Selection`）の解決と、リクエストごとのアダプタ構築を行います。

---

## 主な役割と設計ルール

1. **明示的なモデルカタログ (`provider.Defaults(catalog)`):**
   - 利用可能なモデル一覧は呼び出し側（Host 構成）から明示的に渡されます。カタログ外のモデルは拒否され、別モデルへの暗黙のフォールバックは行いません。
2. **非秘匿の選択メタデータ (`Registry.Build`):**
   - エンドポイント、`credential.Reference`（参照のみ）、リトライ上限、モデルファミリー・機能、選択元を含むバージョン付きの `Selection` を解決します。
   - この `Selection` には秘密情報が含まれないため、そのまま Session / Host メタデータとして永続化できます。
3. **リクエスト単位の認証解決:**
   - 論理的なモデルリクエストごとに現在の認証情報を取得してクライアントへ渡します。
   - 外部の Codex OAuth 認証ファイルはターンごとに読み取り専用で参照されます。
   - 401 エラー時の自動リプレイは行いません。
4. **権限付き HTTP トランスポート:**
   - Host の権限ポリシーを強制する HTTP トランスポートを使用し、認証付きクライアントでは HTTP リダイレクトを無効化します。
   - ワークスペース内の `.env` ファイルによってプロセス環境変数が書き換えられることはありません。
