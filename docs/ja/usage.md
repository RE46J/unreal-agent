# 使い方 (Usage)

**言語:** [English](../usage.md) | 日本語

このガイドでは、**共通キットでインストールした `unreal` コマンド**の日常的な使い方を説明します。（ソースからビルドした実行ファイルのフラグについては [アーキテクチャ — Native launcher](architecture.md#native-launcher) を参照してください。）

---

## セッションの起動と検索

**Session（セッション）** は、ワークスペース（Git ワークツリーのルート、または Git 外では現在のディレクトリ）に紐づく永続的な会話単位です。

1. プロジェクトのディレクトリで Bash を開き、以下を実行します。
   ```bash
   unreal development
   ```
2. `development` という名前のセッションがまだ存在しない場合は、`y` を入力して新規作成します。
3. 2回目以降は、**どのディレクトリからでも** `unreal development` を実行するだけで同じセッションに再接続できます。

### コマンド一覧

| コマンド | 動作 |
| --- | --- |
| `unreal` | 既存のメインセッションを新しい順に一覧表示し、番号で選択して開く |
| `unreal <名前>` | `<名前>` のセッションに接続する（存在しなければ現在のワークスペースに作成するか確認する） |
| `unreal --where <名前>` | `<名前>` のセッションが属するワークスペースのパスを表示する |
| `ucd <名前>` | 現在の Bash シェルを `<名前>` のセッションのワークスペースへ移動（`cd`）する |
| `unreal --workspace-info` | 現在のワークスペースの Workspace / Config / State / Socket の4項目を表示する |
| `unreal --readme` | キットに同梱されている README を表示する |

> **補足:**
> - 引数なしの `unreal` は既存セッションの一覧表示のみを行い、新規作成はしません。
> - 複数のワークスペースに同じ名前のセッションがある場合は、現在いるワークスペースのものが優先されます（別の場所にいる場合は番号選択になります）。
> - `--instance` や `--config` は開発検証用に特定のインスタンス・設定ファイルを直接指定するオプションであり、通常利用では不要です。

## ターミナル画面 (TUI) の操作

### 基本の流れ

1. **スラッシュコマンド:** `/` を入力するとコマンド候補が出ます。`↑` / `↓` で選択、`Tab` で補完、`Enter` で決定します。
2. **モデルと権限の選択:**
   - `/model` — プロバイダ（`Claude` または `Codex`）、モデル、推論の深さ（effort）を切り替えます。
   - `/permissions` — `Read Only`、`Ask for Approval`、`Full Access` を切り替えます。
3. **タスクの送信:** メッセージを入力して `Enter` で送信します。
4. **スクロールとヘルプ:** `Page Up` / `Page Down`（またはマウスホイール）で履歴をスクロールします。`/help` でコマンドとショートカット一覧を確認できます。

### 3つの表示ビュー (`/view`)

- **Split（幅120列以上の初期表示）:** 左側に **Chat**（会話）、右側に **作業ペイン**（メインおよびサブエージェントの稼働カード）を並べて表示します。ウィンドウ幅を120列未満に狭めると自動的に Chat 表示に切り替わります。
- **Chat:** 会話を中心に表示します。幅にかかわらず、入力欄の上に子の1行の要約ドックを表示します。右側の作業ペインは Split 用です。
- **Orchestration:** 画面全体を使ってエージェントの稼働カードと完了ビーズを一覧表示します（`Page Up` / `Page Down` でスクロール可能）。

### フッターのゲージ表示

画面最下部には3つの指標が表示されます（未計測時は `—`）。
- **文脈 (Context):** 現在の入力トークン数と、モデルのコンテキスト上限に対する割合（%）。
- **速度 (Speed):** 出力トークンの生成速度（`tok/s`）。先頭に `~` が付く値はクライアント時計による計測（Claude で使用）です。ツール実行や承認待ちの時間は含まれません。
- **キャッシュ (Cache):** 直近のターンにおけるプロンプトキャッシュのヒット率。

## キーボード操作とテキスト入力

| キー / 操作 | 動作 |
| --- | --- |
| `Enter` | メッセージ送信、またはスラッシュコマンドの実行 |
| `Ctrl+Enter`, `Shift+Enter`, `Alt+Enter`, `Ctrl+J` | 改行を挿入（対応しているターミナルのみ） |
| 行末に `\` を入力して `Enter` | 改行を挿入（すべてのターミナルで利用可能） |
| `@` | ワークスペース内のファイルパスを検索して挿入 |
| `Ctrl+A` | 入力欄のテキストを全選択 |
| 全選択中に文字入力・貼り付け | 選択中のテキストを置換 |
| 全選択中に `Backspace` / `Delete` | 選択中のテキストを削除 |
| `Esc` または矢印キー | 選択状態を解除 |
| `Home` / `End` | 入力欄の先頭 / 末尾へ移動（入力欄が空のときは会話の最上部 / 最新へ移動） |
| `Page Up` / `Page Down` | 会話履歴または Orchestration カードのスクロール |
| `Ctrl+D` | TUI から離れる（セッションはバックグラウンドで継続） |
| `Ctrl+C` | 送信待機中なら待機をキャンセル、通常時はセッションを停止 |

### テキスト貼り付けとファイルドロップ

- **複数行の貼り付け:** 長い複数行テキストを貼り付けると `[Pasted text #1 +N lines]` のように折りたたんで表示され、`Enter` を押すまで勝手に送信されることはありません。
- **Windows から Sandbox へのファイルドロップ:** [`scripts/windows/sandbox-drop.cmd`](../../scripts/windows/sandbox-drop.cmd) を Windows の `SendTo`（送る）フォルダにコピーし、対象の Sandbox 名（例: `development.cmd`）にリネームしておくと、ファイルをドロップするだけで Sandbox 内の `/home/agent/drop/` に転送され、そのパスがクリップボードにコピーされます。

## 会話のコピーとエクスポート

### クリップボードへコピー (`/copy`)

- `/copy` — メッセージ選択画面を開きます。`↑` / `↓` で移動し、`Space` で複数選択して `Enter` でコピーします（先頭の項目を選ぶと公開会話全体をコピー）。
- `/copy last` — 直近のエージェント応答をコピーします。
- `/copy all` — 公開会話全体を Markdown 形式でコピーします。

> **補足:** `/copy` はターミナルの OSC 52 エスケープシーケンスを使用します。お使いのターミナルや `tmux` / `ssh` の設定でクリップボード書き込みが無効になっている場合は、下の `/export` を使用してください。

### Markdown ファイルへ書き出し (`/export`)

- `/export` — **Latest response**（直近の応答）、**Full conversation**（会話全体）、**Choose a response**（応答を選択）から選んでファイルに保存します。
- 直接指定コマンド: `/export last`, `/export all`, `/export pick`
- 出力先は `${XDG_STATE_HOME:-$HOME/.local/state}/unreal-agent/exports` で、保存されたファイルパスが画面に表示されます。

`/copy` も `/export` も、画面外にスクロールした分を含む正規履歴から出力され、内部の推論データや圧縮マーカー、サブエージェントの裏のやり取りは自動的に除外されます。

## 作業の停止・離脱・再開

### 作業を止める (`/stop`)

`/stop` を実行すると、停止する範囲を4つから選べます（初期選択は **Main agent**）。

| 選択肢 | 直接コマンド | 動作 |
| --- | --- | --- |
| **Sub-agents** | `/stop sub` | 稼働中のサブエージェントをすべてキャンセル（メインは継続） |
| **Main agent** | `/stop main` | メインエージェントの現在の応答を中断（サブエージェントは継続） |
| **Main agent and sub-agents** | `/stop main+sub` | メインの中断とサブエージェントのキャンセルを両方実行 |
| **Session** | `/stop session` | セッション全体を停止（`/resume` で再開可能） |

### 離脱・再開・再送

- **離脱 (`Ctrl+D` または `/detach`):** セッションを動かしたままターミナル画面だけを閉じます。
- **再開 (`/resume` または `unreal <名前>`):** 停止中のセッションを再開し、前回選択していた権限モードを復元します。以前使っていたプロバイダが利用できない場合は、停止中に `/model` でプロバイダを切り替えてから `/resume` を実行できます。
- **安全な再送 (`/retry`):** 通信状況などによりメッセージ送信が完了したか不明になった場合、`/retry` を使うと同じ送信 ID で安全に再送できます（二重送信になりません）。

## バックグラウンド作業とサブエージェント

Claude 使用時、メインエージェントは実装や調査タスクを GPT サブエージェント（`lead`, `worker-*`, `collector`）に委譲できます。

- **自動再開:** サブエージェントから完了通知や連絡が届くと、ユーザー入力がなくても親エージェントがバックグラウンドで応答・処理を進めます。
- **裏の作業の折りたたみ:** 日常的な連絡や進捗は、チャット上で `┄ 裏の作業  2ターン · ツール3回 · 報告 [A][C]` のように1行にまとめられます。
- **重要連絡の全文表示:** `【報告】` や `【要確認】` で始まるメッセージは折りたたまれずに全文表示され、未回答の `【要確認】` がある間は画面下部に確認バナーが表示されます。
- **サブエージェントの承認:** サブエージェントのツール実行は親セッションの権限モードに従い、親エージェント経由で制御されます。詳しくは [プロバイダ設定 — Delegated GPT work](providers.md#delegated-gpt-work) と [権限管理](permissions.md) を参照してください。
